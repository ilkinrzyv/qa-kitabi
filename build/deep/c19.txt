### Avtomatlaşdırmanın qiyməti
Avtomatik test “pulsuz” deyil: onu yazmaq, sabitləşdirmək və saxlamaq (dəyişikliklərdən sonra düzəltmək) vaxt aparır. Kobud hesab:
- **Manual:** icra 10 dəqiqə, hər relizdə təkrar, ildə 50 reliz → 500 dəqiqə.
- **Avtomatik:** yazmaq 2 saat + ildə 2 saat saxlama → 240 dəqiqə.
Fayda göz qabağındadır. Amma test ildə bir dəfə işləyirsə, avtomatlaşdırma özünü doğrultmur.

### Seçim meyarları
- **Tezlik:** test neçə dəfə icra olunacaq?
- **Sabitlik:** funksiya və UI tez-tez dəyişirmi?
- **Risk:** səhv nə qədər bahadır (ödəniş, giriş)?
- **Dəqiq nəticə:** nəticə maşınla yoxlana bilirmi? “Dizayn gözəldir” — yox; “cəm 32,39-dur” — bəli.
- **Data həcmi:** eyni ssenari 100 fərqli data ilə işləyirmi?

### Avtomatlaşdırma nəyi tapmır?
Avtomatik test yalnız yazdığın yoxlamaları edir — onun “gözü” yoxdur. Düymənin üstünə düşən reklamı, anlaşılmaz mətni, yavaş hiss olunan animasiyanı exploratory tester tapır. Ən yaxşı komandalar maşına təkrarlanan işi, insana isə düşünmə tələb edən işi tapşırır.

### Konfiqurasiyanın əsas sahələri
```javascript
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  retries: process.env.CI ? 2 : 0,   // CI-da düşən testi 2 dəfə təkrar et
  reporter: 'html',
  use: {
    baseURL: 'https://www.saucedemo.com',
    trace: 'on-first-retry',         // təkrar cəhddə addım-addım iz yaz
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox', use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit', use: { ...devices['Desktop Safari'] } },
  ],
});
```
`baseURL` təyin ediləndə testdə `page.goto('/')` yazmaq kifayətdir. `projects` eyni testləri üç brauzerdə işə salır; yalnız birini seçmək üçün: `npx playwright test --project=chromium`.

### Faydalı əmrlər
- `npx playwright test -g "giriş"` — adında “giriş” olan testlər.
- `npx playwright test --debug` — Playwright Inspector ilə addım-addım icra.
- `npx playwright test --repeat-each=10` — hər testi 10 dəfə işə sal (flaky yoxlaması).

Lokator Playwright-a hansı elementlə işləyəcəyini deyir. Tövsiyə olunan sıra: getByRole, getByLabel, getByPlaceholder, getByText, getByTestId və son çarə kimi CSS lokatoru. İstifadəçinin gördüyünə əsaslanan lokatorlar dizayn dəyişəndə də işləməyə davam edir.
@yadda
- Əvvəl rol və görünən ad — istifadəçi necə görürsə.
- Lokator tam bir elementə uyğun gəlməlidir (strict mode).
- Uzun CSS zəncirləri və sıra nömrələri kövrəkdir.
@dərin
### Strict mode — bir lokator, bir element
Lokator bir neçə elementə uyğun gəlirsə, Playwright hərəkət etmir və “strict mode violation” xətası verir. Məsələn, Swag Labs-da hər məhsulun öz “Add to cart” düyməsi var:
```javascript
await page.getByRole('button', { name: 'Add to cart' }).click();   // xəta: 6 element
```
Həll — konteyner ilə daraltmaq:
```javascript
await page.locator('.inventory_item')
  .filter({ hasText: 'Sauce Labs Backpack' })
  .getByRole('button', { name: 'Add to cart' })
  .click();
```
Bu yazılış istifadəçinin düşüncəsinə uyğundur: “Backpack kartındakı Add to cart düyməsi”.

### getByTestId və Swag Labs
Playwright default olaraq `data-testid` atributunu axtarır, Swag Labs isə `data-test` işlədir. Konfiqurasiyada `use: { testIdAttribute: 'data-test' }` yazandan sonra `page.getByTestId('login-button')` işləyir.

### Kövrək lokatorlar
- `div > div:nth-child(3) > button` — düzülüş dəyişəndə sınır.
- `.first()`, `.nth(2)` — sıra dəyişəndə səhv elementə klik edir.
- Avtomatik yaradılan class adları (`.css-1x2y3z`) — hər build-də dəyişə bilər.

### Lokatoru necə tapmaq və yoxlamaq?
`npx playwright codegen` və UI rejimindəki “Pick locator” düyməsi elementə basanda tövsiyə olunan lokatoru göstərir. Lokatorun tam bir elementə uyğun gəldiyini `await expect(locator).toHaveCount(1)` ilə yoxlamaq olar.

### Arrange – Act – Assert
Hər test üç hissədən ibarətdir:
- **Arrange (hazırlıq):** səhifəni aç, lazım olan vəziyyəti yarat.
- **Act (hərəkət):** yoxlanılan addımı et.
- **Assert (yoxlama):** gözlənilən nəticəni yoxla.
Bu, manual test case-dəki “ilkin şərt — addımlar — gözlənilən nəticə” strukturunun eynisidir.

### Eyni login testi Selenium-da (JavaScript)
```javascript
const { Builder, By, until } = require('selenium-webdriver');

(async () => {
  const driver = await new Builder().forBrowser('chrome').build();
  try {
    await driver.get('https://www.saucedemo.com/');
    await driver.findElement(By.id('user-name')).sendKeys('standard_user');
    await driver.findElement(By.id('password')).sendKeys('secret_sauce');
    await driver.findElement(By.id('login-button')).click();
    await driver.wait(until.urlContains('inventory'), 5000);   // açıq gözləmə
    console.log('PASS: giriş uğurludur');
  } finally {
    await driver.quit();   // brauzeri hər halda bağla
  }
})();
```
Selenium özü test runner deyil: yoxlama və hesabat üçün Mocha, Jest, JUnit və ya pytest kimi runner əlavə olunur. Selenium 4-dən başlayaraq brauzer drayverlərini Selenium Manager avtomatik yükləyir.

### Əsas fərqlər
| | Playwright | Cypress | Selenium |
| --- | --- | --- | --- |
| Gözləmə | avtomatik | avtomatik təkrar yoxlama | çox vaxt açıq yazılır |
| Bir neçə tab və domen | rahat | məhdud (`cy.origin`) | rahat |
| Paralel icra | daxili | əsasən bulud xidməti və ya əlavə alətlərlə | Selenium Grid |
| Dillər | JS/TS, Python, Java, C# | JS/TS | çox |

### Keçid lüğəti
`page.goto` ↔ `cy.visit` ↔ `driver.get`; `fill` ↔ `type` ↔ `sendKeys`; `expect(page).toHaveURL(…)` ↔ `cy.url().should('include', …)` ↔ `driver.wait(until.urlContains(…))`.

### Tipik yanlış anlama
“Selenium köhnədir, öyrənməyə dəyməz.” Bir çox böyük şirkətdə minlərlə Selenium testi işləyir və iş elanlarında o, hələ də tez-tez tələb olunur. Prinsipləri bilmək hər iki dünyada işləməyə imkan verir.
@nümunə
**Tapşırıq.** Kitabdakı Playwright testini — “bloklanmış istifadəçi xəta mesajı görür” — Cypress-ə çevir və hər sətrin qarşılığını göstər.
@addımlar
1. **Struktur:** `test('…', async ({ page }) => { … })` → `describe('Login', () => { it('bloklanmış istifadəçi xəta mesajı görür', () => { … }); });`
2. **Səhifəni aç:** `await page.goto('https://www.saucedemo.com/')` → `cy.visit('https://www.saucedemo.com/')`.
3. **Sahələr:** `getByPlaceholder('Username').fill('locked_out_user')` → `cy.get('[data-test="username"]').type('locked_out_user')`; şifrə sahəsi də eyni qayda ilə: `cy.get('[data-test="password"]').type('secret_sauce')`.
4. **Klik:** `getByRole('button', { name: 'Login' }).click()` → `cy.get('[data-test="login-button"]').click()`.
5. **Yoxlama:** `await expect(page.locator('[data-test="error"]')).toContainText('locked out')` → `cy.get('[data-test="error"]').should('contain', 'locked out')`. Cypress-də `await` yoxdur — `should` şərt ödənənə qədər yenidən yoxlayır.
@növbən
Kitabdakı “məhsul səbətə əlavə olunur” Playwright testini Selenium (JavaScript) ilə yaz: `By.css('[data-test="add-to-cart-sauce-labs-backpack"]')` lokatorundan, `until.elementLocated` ilə açıq gözləmədən və səbət nişanının mətnini `getText()` ilə yoxlamaqdan istifadə et.

### const “dəyişməz” yox, “yenidən təyin olunmaz” deməkdir
```javascript
const user = { name: 'Aysel' };
user.name = 'Leyla';   // işləyir — obyektin içi dəyişir
user = {};             // TypeError: Assignment to constant variable.
```
`const` dəyişəni başqa dəyərə bağlamağa icazə vermir, amma obyektin və massivin içindəkiləri dəyişmək olar.

### typeof-un sürprizləri
```javascript
typeof null;        // 'object' — dilin köhnə xətası
typeof [];          // 'object' — massiv də obyektdir
Array.isArray([]);  // true — massivi belə yoxla
typeof NaN;         // 'number' — “ədəd deyil” də ədəd tipidir
```

### Tester üçün niyə vacibdir?
API cavabında `"price": "19.99"` (mətn) gəlirsə, sənəddə isə ədəd yazılıbsa, bu, müqavilə defektidir. Mətnlə hesablama gözlənilməz nəticə verir: `'19.99' + 1` → `'19.991'`. Tip yoxlaması (`typeof data.price === 'number'`) belə defektləri dərhal tutur.

### Adlandırma qaydaları
Ad hərf, `_` və ya `$` ilə başlayır və böyük-kiçik hərfə həssasdır (`price` ≠ `Price`). JavaScript-də adət camelCase yazılışdır: `totalPrice`, `isLoggedIn`. Mənalı ad kodu sənəd kimi oxunaqlı edir.

### Tipik yanlış anlama
“`null` və `undefined` eynidir.” `undefined` — dəyər heç verilməyib (məsələn, cavabda sahə yoxdur), `null` — sahə var, amma qəsdən boşdur. API testində bu fərq vacibdir: `"middleName": null` ilə sahənin ümumiyyətlə olmaması fərqli hallardır.
@nümunə
**Tapşırıq.** API-dən belə məhsul cavabı gəlib: `{ id: 7, name: 'Termos', price: '19.99', inStock: 'true', discount: null }`. Sənədə görə: id — number, name — string, price — number, inStock — boolean, discount — number və ya null. Hər sahənin tipini `typeof` ilə yoxla və uyğunsuzluqları tap.
@addımlar
1. **Obyekti yarat:** `const product = { id: 7, name: 'Termos', price: '19.99', inStock: 'true', discount: null };`
2. **Tipləri çap et:** `console.log(typeof product.id, typeof product.name, typeof product.price, typeof product.inStock, typeof product.discount);` → `number string string string object`.
3. **Müqayisə et:** `price` mətn gəlir, ədəd gözlənilir — defekt; `inStock` mətn `'true'` gəlir, boolean gözlənilir — defekt.
4. **discount-u ayrıca yoxla:** `typeof null` nəticəsi `'object'` olduğu üçün `product.discount === null` ilə yoxla — null icazəlidir, problem yoxdur.
5. **Nəticə:** 2 müqavilə defekti (price, inStock). Risk: `'19.99' + 1` → `'19.991'`, `'false'` mətni isə şərtdə doğru sayılır.
@növbən
API-dən istifadəçi cavabı gəlib: `{ id: '15', email: 'leyla@example.com', age: 30, isActive: false, phone: undefined }`. Sənədə görə: id — number, email — string, age — number, isActive — boolean, phone — string (məcburi). Tipləri `typeof` ilə yoxla, uyğunsuzluqları tap və hər biri üçün riski izah et.

=== c18s3
@qısa
Operatorlar üç qrupa bölünür: riyazi (+, −, *, /, %), müqayisə (===, !==, >, <, >=, <=) və məntiqi (&&, ||, !). `==` tipləri çevirərək müqayisə edir və səhvləri gizlədir — həmişə `===` işlət.
@yadda
- `===` həm dəyəri, həm də tipi müqayisə edir.
- `+` mətnlə görüşəndə toplamır, yapışdırır: `'5' + 3` → `'53'`.
- `&&` ilə yazılmış aralıq sərhəd dəyərlərini birbaşa göstərir.
@dərin
### `+` operatorunun iki üzü
```javascript
'5' + 3;     // '53' — mətn birləşməsi
'5' - 3;     // 2    — mətn ədədə çevrilir
'5' * '2';   // 10
10 / 0;      // Infinity
'abc' * 2;   // NaN (Not a Number — “ədəd deyil”)
```
Formadan gələn dəyərlər həmişə mətndir. “Səbətdə 2 + 3 = 23 məhsul” tipli baqların səbəbi budur.

### NaN-in qəribəliyi
`NaN === NaN` → `false`. NaN-i yoxlamaq üçün `Number.isNaN(x)` işlədilir. Ekranda “NaN AZN” görmək hesablamaya mətn və ya boş dəyərin qarışdığının əlamətidir.

### Qalıq operatoru (%) harada lazımdır?
`n % 2 === 0` — cüt ədəd; `minutes % 60` — tam saatlardan artıq qalan dəqiqələr. Tester üçün: “hər 3-cü sifarişə endirim” kimi qaydanın sərhədlərini (2, 3, 4, 6) % ilə yoxlamaq olar.

### Məntiqi operatorlar
`age >= 18 && age <= 60` — hər iki şərt doğru olmalıdır (aralıq). `role === 'admin' || role === 'editor'` — biri kifayətdir. `!isBlocked` — inkar. `&&` ilə yazılmış aralıq Fəsil 8-in BVA dəyərlərini birbaşa verir: 17, 18, 60, 61.

### Tipik yanlış anlama
“`==` daha rahatdır, nəticə onsuz da eynidir.” `0 == ''`, `0 == '0'` və `null == undefined` ifadələrinin hamısı `true`-dur — `==` fərqli dəyərləri bərabər sayaraq defektləri gizlədir.
@nümunə
**Tapşırıq.** Formadan gələn iki dəyərin cəmini hesablayan kod səhv nəticə verir: `const a = '2'; const b = '3'; console.log(a + b);` → `23`. Səbəbi izah et, kodu düzəlt və boş və hərfli dəyərlər üçün yoxla.
@addımlar
1. **Səbəb:** forma dəyərləri mətndir; `+` mətnləri yapışdırır: `'2' + '3'` → `'23'`.
2. **Düzəliş:** əvvəl ədədə çevir — `Number(a) + Number(b)` → `5`.
3. **Boş sahə:** `Number('')` → `0` — boş sahə səssizcə 0 kimi qəbul olunur. Bu, validasiya sualıdır: boş sahə xəta verməli deyilmi?
4. **Hərfli dəyər:** `Number('3a')` → `NaN`, cəm də `NaN` olur — `Number.isNaN(result)` ilə yoxlayıb istifadəçiyə xəta göstərmək lazımdır.
5. **Test dəyərləri:** '2' və '3' → 5; '' → xəta (və ya tələbə görə); '3a' → xəta; ' 4 ' (boşluqlu) → `Number(' 4 ')` → 4 — bu qəbul olunurmu, tələbdə qeyd et.
@növbən
Endirim kodunun nəticəsini təxmin et, sonra işə salıb yoxla: `const price = '50'; const discount = '10'; console.log(price - discount, price + discount, price * discount / 100);` Hansı nəticə “səhv”dir və niyə? Kodu elə düzəlt ki, hər üç ifadə ədədlərlə işləsin.

Mətnlərlə iş üçün əsas alətlər: `length` (uzunluq), `trim()` (kənar boşluqları silir), `toLowerCase()`/`toUpperCase()`, `includes()` (içində varmı) və template literal ilə `${}` daxil etmə. Azərbaycan hərfləri üçün `toLocaleLowerCase('az')` işlədilir.
@yadda
- Email və login müqayisəsindən əvvəl `trim()` və kiçik hərfə çevirmə.
- “İ/i” və “I/ı” cütləri üçün dil qaydası ilə çevir: `'az'`.
- `length` boşluqları və bəzi simvolları gözlənilmədən sayır.
@dərin
### Faydalı metodlar
```javascript
const s = 'order-2026-1001';
s.startsWith('order');      // true
s.endsWith('1001');         // true
s.split('-');               // ['order', '2026', '1001']
s.slice(0, 5);              // 'order'
s.replace('order', 'ORD');  // 'ORD-2026-1001'
'7'.padStart(3, '0');       // '007'
```
`split` mətni hissələrə bölür — tarix, nömrə və ID-ləri parçalamaq üçün; `padStart` isə “007” kimi formatlı nömrələr üçündür.

### Uzunluq sürprizləri
```javascript
'Salam'.length;     // 5
'😀'.length;        // 2 — emoji iki “vahid” tutur
[...'😀'].length;   // 1 — real simvol sayı
```
“Ad 20 simvola qədər” qaydasında emoji ilə yazılan ad sərhəddə fərqli sayıla bilər: UI 20 göstərir, server 21 sayır. Sərhəd testlərinə emoji də əlavə et.

### Azərbaycan hərfləri və sıralama
```javascript
'i'.toUpperCase();             // 'I' — ingilis qaydası
'i'.toLocaleUpperCase('az');   // 'İ'
['Şahin', 'Cavid', 'Səbinə', 'Çingiz'].sort((a, b) => a.localeCompare(b, 'az'));
// ['Cavid', 'Çingiz', 'Səbinə', 'Şahin']
```
`localeCompare(…, 'az')` Azərbaycan əlifbası ilə sıralayır. Adi `sort()` isə simvol kodlarına görə sıralayır və nəticə `['Cavid', 'Səbinə', 'Çingiz', 'Şahin']` olur — “Ç” və “Ş” sona düşür.

### Tipik yanlış anlama
“Mətnləri `===` ilə müqayisə etmək həmişə kifayətdir.” `'Aysel '` və `'Aysel'`, `'ALI'` və `'ali'` fərqli mətnlərdir. Müqayisədən əvvəl qayda müəyyən olunmalıdır: boşluqlar silinirmi, böyük-kiçik hərf nəzərə alınırmı?
@nümunə
**Tapşırıq.** Login formasında email müqayisəsi belə yazılıb: `if (inputEmail === savedEmail)`. Bazada `aysel@example.com` saxlanılır, istifadəçi isə `  Aysel@Example.com ` yazır. Problemi göstər, düzəlt və 4 test dəyəri ilə yoxla.
@addımlar
1. **Problem:** `'  Aysel@Example.com ' === 'aysel@example.com'` → `false` — istifadəçi düzgün email yazsa da, daxil ola bilmir.
2. **Normallaşdırma funksiyası:** `const normalize = e => e.trim().toLowerCase();`
3. **Düzəlişli müqayisə:** `normalize(inputEmail) === normalize(savedEmail)` → `true`.
4. **Test dəyərləri:** `'aysel@example.com'` → true; `'  Aysel@Example.com '` → true; `'AYSEL@EXAMPLE.COM'` → true; `'aysel@example.co'` → false.
5. **Tələb sualı:** email-in “@”-dan əvvəlki hissəsi nəzəri olaraq böyük-kiçik hərfə həssas ola bilər, amma praktikada əksər sistemlər onu həssas saymır — komandanın qaydasını tələbdə qeyd et.
@növbən
Axtarış sahəsi istifadəçinin yazdığı sözü məhsul adlarında `includes()` ilə axtarır və müqayisədən əvvəl hər ikisini `toLowerCase()` ilə kiçildir. “İSTİ ÇAY” məhsulunu istifadəçi “isti” yazanda tapa bilmir. Səbəbi kodla göstər (`toLowerCase` və `toLocaleLowerCase('az')` nəticələrini müqayisə et), kodu düzəlt və 4 test dəyəri təklif et.

=== c18s5
@qısa
`if / else if / else` kodun hansı yolla gedəcəyini şərtə görə seçir. Hər yol ayrıca test halıdır: 3 yolu olan kod üçün branch coverage-də ən azı 3 test lazımdır. Sərhəd dəyərləri isə şərtlərdəki rəqəmlərdən çıxır.
@yadda
- Hər `if` budağı — ayrıca test.
- `>=` ilə `>` fərqi sərhəd defektlərinin əsas mənbəyidir.
- `0`, `''`, `null`, `undefined`, `NaN` şərtdə “yalan” sayılır.
@dərin
### “Doğru” və “yalan” sayılan dəyərlər (truthy/falsy)
`if`-ə yalnız `true` və `false` yox, istənilən dəyər vermək olar. Yalan sayılanlar: `false`, `0`, `''`, `null`, `undefined`, `NaN`. Qalan hamısı doğrudur — `'0'`, `'false'` və `[]` də!
```javascript
const quantity = 0;
if (quantity) {
  console.log('Miqdar göstərilib');
} else {
  console.log('Miqdar göstərilməyib');   // bu çap olunur!
}
```
Kodun niyyəti “miqdar sahəsi doldurulubmu?” idisə, `0` dəyəri səhvən “doldurulmayıb” kimi emal olunur. Tester üçün: 0 həmişə xüsusi test dəyəridir.

### Şərtlərin sırası
```javascript
if (total >= 50) { fee = 2; }
else if (total >= 100) { fee = 0; }   // heç vaxt işləməyəcək!
```
İkinci şərtə heç vaxt növbə çatmır: 100-dən böyük hər məbləğ artıq birinci şərtə düşür. Belə “ölü budaqları” branch coverage tapır — test etmək mümkün olmayan budaq dizayn xətasıdır.

### switch
Bir dəyişəni çox dəyərlə müqayisə etmək üçün `switch` işlədilir:
```javascript
switch (status) {
  case 'paid': label = 'Ödənilib'; break;
  case 'shipped': label = 'Göndərilib'; break;
  default: label = 'Naməlum';
}
```
`break`-i unutmaq növbəti `case`-in də icrasına səbəb olur — klassik defektdir.

### Tipik yanlış anlama
“`else` yazmaq vacib deyil.” `else` olmayanda gözlənilməz dəyər (mənfi yaş, boş status) səssizcə heç bir budağa düşmür. Tester “heç bir şərtə uyğun gəlməyən dəyər”i də yoxlamalıdır.
@nümunə
**Tapşırıq.** Çatdırılma haqqı: 50 AZN-dən az — 5 AZN, 50–99,99 AZN — 2 AZN, 100 AZN və çox — pulsuz. Funksiyanı `if/else` ilə yaz, bütün budaqları və sərhədləri əhatə edən test dəyərlərini seç.
@addımlar
1. **Kod:** `function deliveryFee(total) { if (total >= 100) { return 0; } else if (total >= 50) { return 2; } else { return 5; } }`
2. **Budaqlar:** 3 yol var — branch coverage üçün ən azı 3 test: 30 → 5, 70 → 2, 150 → 0.
3. **Sərhədlər:** 49.99 → 5; 50 → 2; 99.99 → 2; 100 → 0.
4. **Xüsusi dəyərlər:** 0 → 5 (boş səbətə haqq alınmalıdırmı?); −10 → 5 — kod mənfi məbləği qəbul edir, tələbə görə isə xəta olmalıdır. Bunu sual və ya defekt kimi qeyd et.
5. **Sıranı yoxla:** şərtlər böyükdən kiçiyə yazılıb — ölü budaq yoxdur.
@növbən
Parol gücü funksiyası yaz: 8 simvoldan az — “zəif”, 8–11 simvol — “orta”, 12 və çox — “güclü”. `if/else` ilə yaz, bütün budaqlar və sərhədlər üçün test dəyərlərini (uzunluqlarla) seç və boş parol üçün nə olmalı olduğunu müzakirə et.

=== c18s6
@qısa
Funksiya — adı olan, təkrar istifadə olunan kod blokudur: parametrlər qəbul edir və `return` ilə nəticə qaytarır. Ox funksiyası (`=>`) qısa yazılışdır. Yaxşı funksiya bir iş görür və eyni girişə həmişə eyni nəticə verir — belə funksiyanı test etmək asandır.
@yadda
- Parametr — giriş, `return` — çıxış.
- Ötürülməyən parametr `undefined` olur və hesablamada `NaN` yaradır.
- Eyni giriş → eyni nəticə: test üçün ideal funksiya.
@dərin
### Default parametrlər
```javascript
function calculateDiscount(price, percent = 0) {
  return price - (price * percent / 100);
}
calculateDiscount(100);   // 100 — percent verilməyib, 0 götürülür
```
Default dəyər olmasaydı: `100 - (100 * undefined / 100)` → `NaN`. Ekranda “NaN AZN” görünən baqların bir səbəbi də budur.

### return-süz funksiya
`return` yazılmayıbsa, funksiya `undefined` qaytarır. `console.log(calculateTotal(…))` → `undefined` görürsənsə, ilk yoxlanılacaq yer `return`-dür.

### “Saf” funksiya — tester-in dostu
Saf funksiya yalnız parametrlərindən asılıdır və kənarda heç nəyi dəyişmir: `calculateDiscount(100, 10)` həmişə 90 qaytarır, ona test yazmaq çox asandır. Cari vaxtdan, təsadüfi ədəddən və ya qlobal dəyişəndən asılı funksiyanı test etmək çətindir. Məsələn, “bu gün endirim günüdürmü?” funksiyasına tarixi parametr kimi ötürmək onu test edilə bilən edir.

### Funksiya — parametr kimi
JavaScript-də funksiyanı başqa funksiyaya ötürmək olar: `prices.filter(p => p > 50)` — burada `p => p > 50` funksiyadır. Playwright-dakı `test('ad', async ({ page }) => { … })` yazılışı da eyni məntiqdir: test özü bir funksiyadır.

### Tipik yanlış anlama
“Funksiya işləyirsə, iş bitib.” Funksiyanın da sərhədləri var: mənfi qiymət, 100%-dən böyük endirim, mətn tipli parametr. `calculateDiscount(100, 150)` → `-50` — mənfi qiymət!

@qısa
Şəbəkə və brauzer əməliyyatları vaxt aparır, JavaScript onları asinxron icra edir və nəticə üçün “vəd” (Promise) qaytarır. `await` nəticə gələnə qədər gözləyir, `async` isə funksiyanın içində gözləmə olduğunu bildirir.
@yadda
- Promise üç vəziyyətdə olur: gözləmədə, uğurlu, uğursuz.
- `await`-siz kod nəticəni gözləmədən irəli qaçır.
- Xətanı `try/catch` ilə tut; `fetch` 404-də xəta vermir — statusu yoxla.
@dərin
### await-i unutmaq nə edir?
```javascript
async function getUser() {
  const response = fetch('https://jsonplaceholder.typicode.com/users/1');   // await yoxdur!
  console.log(response);   // Promise { <pending> }
}
```
Dəyər əvəzinə “hələ yerinə yetirilməmiş vəd” alınır. Playwright-da `await`-siz `click()` klikin bitməsini gözləmir — növbəti yoxlama vaxtından əvvəl işləyir və test təsadüfi düşür.

### Xətaların tutulması
```javascript
async function getUser(id) {
  try {
    const response = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    if (!response.ok) {
      console.log('Status:', response.status);   // məsələn, 404 — fetch bunu xəta saymır!
      return null;
    }
    return await response.json();
  } catch (error) {
    console.log('Şəbəkə xətası:', error.message);   // məsələn, internet yoxdur
    return null;
  }
}
```
`fetch` yalnız şəbəkə xətasında (bağlantı yoxdur) uğursuz olur; 404 və 500 cavabları “gəlmiş cavab” sayılır. Ona görə `response.ok` (status 200–299) və ya `response.status` mütləq yoxlanır.

### Paralel gözləmə
`await Promise.all([getUser(1), getUser(2)])` iki sorğunu eyni anda göndərir və hər ikisinin cavabını gözləyir — ardıcıl iki `await`-dən daha sürətlidir.

### Tipik yanlış anlama
“Gözləmək üçün 3 saniyəlik sabit fasilə kifayətdir.” Sabit gözləmə ya vaxt itirir, ya da yavaş mühitdə çatmır — flaky testlərin əsas səbəblərindəndir. Düzgün yol şərti gözləmədir: “element görünənə qədər” (Fəsil 19).
@nümunə
**Tapşırıq.** Bu funksiya istifadəçinin adını çap etməlidir, amma xəta verir. Səhvləri tap, düzəlt və mövcud (1) və mövcud olmayan (999) istifadəçi üçün davranışı yoxla.

```javascript
async function showUserName(id) {
  const response = fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
  const user = response.json();
  console.log(user.name);
}
showUserName(1);
```
@addımlar
1. **Xətanı oxu:** `TypeError: response.json is not a function` — `response` cavab deyil, Promise-dir, çünki `fetch`-dən əvvəl `await` yoxdur.
2. **Düzəliş 1:** `const response = await fetch(...)`.
3. **Düzəliş 2:** `response.json()` da Promise qaytarır — `const user = await response.json();`.
4. **Status yoxlaması:** `json()`-dan əvvəl əlavə et: `if (!response.ok) { console.log('İstifadəçi tapılmadı:', response.status); return; }` — 999 üçün server 404 qaytarır, `fetch` isə xəta vermir.
5. **Nəticə:** `showUserName(1)` → `Leanne Graham`; `showUserName(999)` → `İstifadəçi tapılmadı: 404`. Status yoxlaması olmasaydı, 999 üçün `undefined` çap olunardı — cavab gövdəsi boş obyektdir.
@növbən
Bu kodda iki problem var: (1) çap ardıcıllığı gözlənilən kimi deyil, (2) xəta halı emal olunmur. Nəyin hansı ardıcıllıqla çap olunacağını təxmin et, sonra işə salıb yoxla və kodu `await`, `response.ok` və `try/catch` ilə düzəlt.

```javascript
async function loadPosts() {

  const posts = await res.json();
  console.log('Yazıların sayı:', posts.length);
}
loadPosts();
console.log('Hazırdır!');
```

### check()-i təkmilləşdirək: yekun hesabat
```javascript
let passed = 0;

    console.log('FAIL:', description, '| gözlənilən:', expected, '| faktiki:', actual);
```

Real test alətləri də sonda belə yekun verir: “6 passed, 1 failed”.

```javascript
const assert = require('node:assert');

function isValidAge(age) {
  return Number.isInteger(age) && age >= 18 && age <= 60;
}
```
